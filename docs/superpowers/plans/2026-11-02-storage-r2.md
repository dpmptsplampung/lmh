# Storage Cloudflare R2 + Lampiran Live Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Semua berkas LMH (dokumen investasi, foto UMKM, foto absensi, dan lampiran live chat baru) disimpan di Cloudflare R2, tanpa Supabase Storage (batas 1 GB).

**Architecture:** Satu lapisan tipis `src/lib/storage/` (klien S3 ke R2 + aturan per "area") menggantikan semua pemanggilan `supabase.storage`. Hak akses yang dulu ada di policy `storage.objects` pindah ke route API: upload langsung dari browser memakai **presigned PUT** (ukuran dan tipe ikut ditandatangani, lalu diverifikasi server saat konfirmasi); baca berkas privat lewat route yang mengecek role/kepemilikan lalu men-stream byte (pola `page-image`). Dua bucket R2: `PRIVATE` (prefix per area) dan `PUBLIC` (hanya `umkm-photos/`, dibaca lewat domain publik).

**Tech Stack:** Next.js 16 (route handler, `params` berupa Promise), `@aws-sdk/client-s3` + `@aws-sdk/s3-request-presigner` (R2 kompatibel S3), zod 4, Vitest (`--pool=vmForks`), Supabase (hanya untuk DB + auth).

**Spec:** Belum ada dokumen spesifikasi terpisah; keputusan berasal dari percakapan (2026-11-02): pakai R2, 1 bucket privat + 1 bucket publik, tambah lampiran chat, tidak memakai Supabase Storage. Inventaris pemakaian: bagian "Inventaris" di bawah.

## Review Focus

Input/kondisi yang tidak disebut spesifikasi tapi mungkin muncul; tiap baris punya tes di task pemiliknya.

1. Path berisi `..`, awalan `/`, `\`, atau karakter kontrol → ditolak sebelum menyentuh R2 (Task 2).
2. Klien menandatangani untuk ukuran/tipe A lalu mengunggah berkas lain (mis. HTML bernama `.jpg`) → konfirmasi memeriksa ukuran + magic bytes, objek dihapus bila tidak cocok (Task 2).
3. Pengunjung A meminta lampiran chat milik sesi pengunjung B (menebak `pesan_id`) → 404, tanpa bocor ada/tidaknya (Task 7).
4. Pesan chat hanya berisi lampiran (tanpa teks) → tidak memicu bot/RAG/eskalasi otomatis dan tidak ditolak oleh validasi `isi` (Task 7).
5. R2 gagal/timeout saat menghapus dokumen investasi → baris DB tetap terhapus (urutan DB-dulu dipertahankan), kegagalan dicatat sebagai `warn` (Task 3).
6. Tautan foto UMKM berskema `javascript:`/`data:`/`http:`, berisi `user:pass@`, atau menunjuk `localhost`/IP privat → ditolak di UI dan oleh `CHECK` DB; tautan eksternal yang mati → placeholder "Foto tidak tersedia", halaman tidak rusak; tautan eksternal tidak membocorkan Referer halaman LMH (Task 4).
